# g3 — T1 review

Subject: g3 (Rust), /data/samples/agents/g3, upstream https://github.com/dhanji/g3.
Tier T1 (census 51,470 non-test / 17,819 test LOC; my recount: 84,040 total .rs LOC, tests dirs alone 26,635 — see census notes).

## Anchor question

**Which anchor is this closer to, and why?** nanocoder (60.5) — a solo-author project with genuinely interesting context and orchestration machinery (g3's stronger on token economy, cleaner workspace) dragged down by weak enforcement and no CI, though a notch lower because g3 has no sandbox at all where nanocoder at least ships an opt-in jail.

## Structure

8-crate workspace (crates/g3-{cli,core,planner,providers,config,execution,computer-control,studio}); root src/main.rs is 6 LOC. g3-core dominates (49.7k) and `src/lib.rs` is a 4,155-LOC god file: Agent struct, loop, cache-breakpoint policy, mid-turn injection, duplicate detection all fused (`crates/g3-core/src/lib.rs:2762` `stream_completion_with_tools`, labeled loop at `:2793` with `MAX_ITERATIONS` cap at `:2795`). Elsewhere boundaries are real: compaction (`compaction.rs`), context window (`context_window.rs` 1,694), dehydration (`acd.rs` 691), mailbox (`pending_input.rs`) are separate modules with separate tests.

## Core loop (read)

`execute_single_task` (lib.rs:1211) → `stream_completion_with_tools` (lib.rs:2762): pre-loop `ensure_context_capacity` (lib.rs:1594), `'stream_iteration` loop (lib.rs:2793) streaming chunks, dedupe-guarding tool calls (DUP IN CHUNK/MSG/ITER, lib.rs:1666-1730, streaming.rs:666-682), executing tools, auto-continue, MAX_ITERATIONS breaker. Fallback-model reset funneled through one place per turn (lib.rs:1225-1232). The loop is legible and heavily commented with incident postmortems (e.g., poisoned Anthropic cache_control session, lib.rs:1253-1266) — the comments are evidence of a maintainer debugging real failures, not marketing.

## Compaction / token economy (read)

Three tiers behind a proportional ladder:
1. **Thinning**: large tool results offloaded to disk at a 50→80% step ladder (context_window.rs:447-455; scope FirstThird="leaned"/All="skinnify", context_window.rs:36-48). Shell output >8KB spills to file with a read_file pointer (tools/shell.rs:15-70).
2. **Summary compaction** at `compaction_threshold_percent` (context_window.rs:439-444, deliberately proportional — comment forbids reintroducing an absolute token guard); provider-capped summary tokens (compaction.rs:55-78).
3. **ACD — Aggressive Context Dehydration** (acd.rs:1-19): post-compaction, older messages become linked-list fragment files under `.g3/sessions/<id>/fragments/` replaced by metadata stubs; a `rehydrate` tool (tools/acd.rs:15) restores them, gated by a remaining-capacity check (acd.rs:281-286). Has its own cost model (`acd_cost_model_test.rs`) and characterization tests that pinned fidelity defects before fixing them (acd_fidelity_characterization_test.rs:1-10) — the whole corpus rarely sees a context mechanism with a written cost analysis plus regression suite.

Cache discipline is real: rolling `cache_control` breakpoint budget (max 3 rolling + system block, lib.rs:639-657), cleared-and-slid on user turns (lib.rs:1252-1266) after a live 400-error incident; cache stats surfaced in `/stats` (stats.rs:19, format_cache_stats). Token accounting prefers provider-reported usage and falls back to a heuristic (context_window.rs:207, 377-399). Trigger is usage-percentage based, not projected-request based — one rung below pi's "measures what the model would receive".

## Permission / safety code (read)

There is no permission layer around execution. `execute_shell` (tools/shell.rs:73-133) runs the model's command through `CodeExecutor::execute_bash_streaming_in_dir` unconditionally; `background_process` (tools/shell.rs:157-211) likewise. No approval prompt, no allowlist/denylist, no sandbox, no SECURITY.md anywhere in the tree. The only enforcement-shaped thing is a plan-mode approval gate (tools/plan.rs:1052-1135): after tool execution in plan mode, git-dirty files without an approved `plan.g3.md` produce a "IMPLEMENTATION BLOCKED" message injected back into the conversation (lib.rs:3830-3836) — a soft, LLM-mediated block; the test suite itself pins "warns without reverting" (plan.rs:1564). Autonomous mode ("new_autonomous", lib.rs:344) plus coach mode (cli/autonomous.rs:87-246, LLM-coach approves implementation) is the default posture: full auto, blast radius = user's machine. This is below the nanocoder 5 rung (which at least has a jail, opt-in and fail-open); above codel's 2 because g3 doesn't claim safety it doesn't have — honesty without machinery.

## Verification

~27.6k LOC in tests/ dirs across crates (56 files in g3-core/tests alone), and they prove things, not existence: mock-provider integration tests drive the real streaming loop without an LLM (mock_provider_integration_test.rs:1-30, faux-provider-testing); fallback-model tests state a 4-point contract and drive the real retry path (fallback_model_test.rs:1-15); eager-session-write tests document a measured data-loss bug (10/219 sessions lost a 210-message conversation) and pin the two properties of the fix (eager_session_write_test.rs:1-25). UTF-8-safe truncation, stuttering streaming parser, mid-turn injection ordering, resume-preserves-tool-calls — many are named after real defects. **But there is no CI at all**: no `.github/`, no workflow files; `scripts/` has only install/signing helpers. Nothing runs this suite automatically. Verification ceiling for unrun tests: 5.

## Orchestration / operability / interop

- Mid-turn user inbox (pending_input.rs:1-31): external processes (butler.app) drop one file per message into `.g3/sessions/<id>/inbox/`; agent drains per streaming iteration; delivery semantics at-most-once, deliberately, with the failure-mode tradeoff written out. Crash-safe via `create_new` + atomic-write reasoning. Distinctive.
- Async research tasks injected at natural break points (pending_research.rs:1-9), background process manager, `studio`: multi-session manager over git worktrees with crash-recovery ids (studio/src/main.rs:30-33, sdlc.rs:134).
- Persona agent pack compiled in via include_str! (cli/embedded_agents.rs:16-28): breaker (adversarial QA with a "DO NOT CHANGE PRODUCTION CODE" directive, agents/breaker.md:1-20), carmack, hopper, lamport... Workspace overrides take priority.
- Session resume: symlink `.g3/session` + latest.json (session_continuation.rs:1-19), eager per-iteration session.json with unanswered-tool-call trim on restore (Anthropic tool_use pairing invariant, eager_session_write_test.rs:20-25). No checkpoint/revert of file changes.
- Interop: no MCP, no ACP, no SDK. Headless contract is `--stream-events` NDJSON sidecar for butler.app (event_stream.rs:1-27, fail-silent by design) + the inbox dir. Providers: Anthropic/OpenAI/Gemini/Databricks/embedded llama.cpp + OAuth (g3-providers/src). Custom-protocol interop with exactly one known consumer.

## Originality

ACD dehydrate/rehydrate with cost model + characterization tests is among the most distinctive context mechanisms in the corpus. Rolling cache-breakpoint budget enforced against a live-incident is rare (most subjects stamp cache_control blindly). Invariants/rulespec + action-envelope evidence system (tools/invariants.rs:1-11) ties plan verification to a checked-in `analysis/rulespec.yaml`. Mid-turn FS mailbox with argued at-most-once semantics. Persona pack is theatrical but wired.
