## Anchor question

**Closer to pi than to any other anchor**: same solo-vision philosophy (thin core, everything-an-extension, honest "this is not enforcement" security writing, cache warmth treated as a first-class concern), and hotdog holds pi's errata bar of loop/product separation better than pi itself (largest file 1,660 LOC) -- but it lands well below pi's 78.5 on interop (no ACP/RPC surface, no SDK), verification breadth (one CI job vs pi's matrix), and community/durability.

## Core loop (line-level read)

`src/core/agent.ts` (928 LOC): `run()` :303 -> `while (iteration < maxIterations)` :334 -> `_prepareIteration` :526 -> `_performLlmCall` :561 -> `_handleLlmResponse` :606 -> `_executeTools` -> `ToolExecutor.execute` (`src/core/tool-executor.ts:59`).

- Re-entrancy guard `#running` (:317-322) with an *agent*-class error ("an overlapping run is a bug, not a runtime condition"); per-run `AbortController` with per-run forwarded listener removed in `finally` (:571-591) -- documented listener-accumulation fix.
- PROVIDER_ERROR repair seam (:329-339): exactly one retry, handler may mutate params (tool-call-repair drops corrupt stored calls). PROVIDER_RESPONSE pipeline lets extensions replace the response before it becomes an assistant message (:612-617).
- **finish_reason=length tool-call refusal** (:43-56, :641-652): streamed args may be silently truncated, so *no* call from that response executes; every call gets a synthesized re-issue tool result keeping call/result pairing valid for strict backends. Same orphan discipline on `maxToolCallsPerIteration` truncation (:653-666) and on `stopLoop` mid-batch (`tool-executor.ts:93-106`).
- Empty-completion budget (`maxEmptyRetries`, :355-385): after-tools empty turns append a harness `system-notice` nudge that also repairs the context tail strict templates reject; when the budget is spent the run returns `{type:"empty_response"}` "instead of completing empty" -- honest termination taxonomy `TurnEndReason` (:26-36) covers completion/tool_return/continue/cancelled/error/max_iterations/empty_response.
- Max-iteration grace: one tools-off wrap-up call (:470-520) whose result is deliberately not run through `_handleLlmResponse` (tool-call-repair could forge calls into the summary) -- the comment knows the attack.
- Steering queue drained between LLM calls, never between assistant(tool_calls) and tool results (:176, :535-540). `claimTurn()` at TURN_END (:706-712) makes exactly one hook own a continuation -- prevents loop/handoff double-fire.
- Tool availability is resolved once per batch from the model-visible defs (:761-764), and unavailable names get fuzzy near-match suggestions (`tool-executor.ts:349-376`) -- model-recoverable error design throughout.

## Compaction / context (line-level read)

`src/extensions/compaction/` (508 + strategies + utils):

- Trigger `shouldCompact` (`utils.ts:63-70`) estimates against `contextLimit - reserveTokens` **at the session's wire size**: tool-result parts are measured through the resolved WireFormat (`estimatorFor`, utils.ts:91-94) -- the pi-style "measure what the model actually receives," cheaper cousin (chars/4 + wire rendering).
- Five strategies behind one registry (summarize, summarize-short, token-aware, trim, drop; `index.ts:56-60`). Summarize keeps recent verbatim; boundary never splits a tool_call/result pair (`utils.ts:42-58` back-up loop; runtime safety net aborts compaction rather than orphan a tool message, `index.ts:174-183`).
- **Overflow rescue is LLM-free** (`index.ts:376-430`): on `isContextOverflowError`, trim (minimum drop) then, only if trim's own estimate says it already fits (i.e. the estimate lost the race), blunt drop -- gated by `canCompact` so a misclassified overflow can't silently eat a young session's history. Params are mutated so the single core retry ships the compacted context.
- Summary injection carries provenance: wrapper tag as trusted harness text, summary body as an `untrusted` part mangled at the wire (:196-210); the summarization dump is pre-mangled and rides harness content so genuine wrappers survive (:120-135, `utils.ts:74-121`) -- a subtlety most subjects get wrong twice.
- `ensureUserTurnGuard` (:70-87): strict llama.cpp/LM Studio templates rejected histories ending in assistant/tool; the guard itself carries harness provenance so it never gets mangled.
- No cloud prompt-cache discipline: `cache_control` / `prompt_cache_key` appear nowhere (grep empty). The cache story is local-first instead: system-prompt caching with invalidation exactly at model switch / resume / clear (agent.ts :236-260, context-manager), workflow warm-retries that keep the KV cache warm (engine.ts:449-470), and loaded-model placement (below). Cost visibility: net-of-cached token accounting (`token-tracker.ts:56-58`), no pricing (consistent with local-first).

## Permission / safety enforcement (line-level read)

- **Default posture: nothing mediates tool calls.** `userGate.enabled` defaults **false** (`src/extensions/user-gate/extension.json:10-14`); with stock config every tool -- including bash -- runs unconfirmed. There is **no OS sandbox anywhere** (no bwrap/seatbelt/namespace code in src). Absent is absent.
- The opt-in gate is nonetheless the best-written approval layer in the corpus I've read: fail-closed on every axis (non-interactive UI, throwing/rejecting/empty answer, abort mid-prompt, malformed config -> blocks ALL calls, handler's own exception -> block; `user-gate/index.ts:1-16, 186-196, 264-279`, proven by an explicit fail-closed matrix, `tests/extensions/user-gate.test.ts:245-388`); `TOOL_CALL` pipeline runs `failOnError: true` (`tool-executor.ts:155-159`). Default-deny mode prints the exact config line that would have allowed the call -- headless-debuggable. Session memo keyed on the *full* target set so `git status` can't silently cover `git push` (:88-95).
- **Bash triage is a bail-based tokenizer, not a regex deny-list** (`src/utils/approvals/bash.ts:1-10`): segments on operators, tracks `cd`, and BAILS (-> ask/deny) on expansions, substitutions, globs, heredocs, `eval/env/xargs`, inline-code flags, `find -exec`; quoting is tracked at character level because that's the only place `*` is data vs glob (:52-146). "Nothing below it enforces any boundaries" -- says the header, honestly. Reuses the workspace deny dialect rather than growing a second grammar (`workspace.ts:186-200`).
- **Always-on containment**: every file tool resolves through `Workspace.resolveSafe` (`workspace.ts:285-355`): multi-root, direct-escape rejection, ancestor realpath walk, dangling-final-symlink chain walk (:330-348), denylist re-checked against the *real* path (`notes.md -> .ssh/id_rsa` closes), gitignore-style ordered negation rules, built-in `DEFAULT_DENY_PATTERNS` (.ssh/.env*/.git/...; :165-179). Tested (`tests/utils/workspace.test.ts`). This is the one guard that binds by default -- and bash bypasses it trivially, which the docs state.
- **Injection defense is structural, not screening**: `MarkerMangler` (`src/core/marker-mangler.ts`) aliases every protected marker (`tool_call`, `thinking`, `previous-context-summary`, WireFormat markers, model control tokens) to per-session 16-char CSPRNG aliases -- unbiased rejection sampling (:34-46) -- applied per-message at the wire serializer including tool-call names/args (`llm-client/serialize.ts:61-98`); unescape happens once on assembled stream output, not per chunk (alias straddling deltas, `agent.ts:744-756`). Provenance decides trust: only `system`/`harness` content is exempt (`serialize.ts:110-112`); harness messages embed model payloads as `untrusted` parts. ChatML control tokens are escaped too (HEAD commit `efc15c0`).
- **Two-arm anti-spoofing**: `src/utils/spoof.ts` neutralizes bidi overrides/isolates, zero-widths, C0/C1, BOM at *human render* boundaries only (approval prompts, tool display, webui; `spoofSafe` at `user-gate/index.ts:108` + 3 more call sites), replacing with visible counted `[U+XXXX]` tokens; INVARIANT: render-time only, session log keeps original bytes for audit. Tested (`tests/utils/spoof.test.ts`, `user-gate.test.ts:87`).
- `sandboxMode` config filters side-effect tools from defs (`agent.ts:873-885`, `tool-registry.ts:251`) -- a tool-availability tier, not enforcement. Websocket server has an AUTH gate that holds even when clients skip the upgrade token check (`websocket/server.ts:716-723`, `websocket-auth.test.ts`).

## Orchestration

- **Workflow engine** (`src/extensions/workflows/engine.ts`, 1,393 LOC -- ships the very orchestration this field study runs on): one run = one dir, append-only `run.jsonl` state journal (:6-14); ownership claim file with pid+host+heartbeat liveness, stale reclaimed, live-owner refusal (:270-278), owner released in ALL exit paths incl. resume-guard throws (:306-311, pid-liveness covers hard kills); **reconcile-resume validates completed claims against the filesystem** (mtime-fresh `FileClaim`s) and reuses only what matches; nodes are *parked* TaskManager tasks that yield their lane slot while idle; warm follow-up retries keep the same session (KV cache warm); cold re-admission after infra failure; per-node accumulated-runtime cap that banks time only while a turn actually runs (:838-880); judges as first-class nodes with `pass|fail|reject` verdict files, per-producer-attempt budgets, deadlock-analyzed dep handling (:540-560); spliced model-authored content rides `untrusted` parts so a poisoned run-dir file can't impersonate harness prose (:186-196, tested :881,928). Crash recovery = re-run same dir (manual), no daemon.
- **TaskManager** (1,660 LOC): provider-lane admission (pin > group > requires > chain-expansion, `model-resolver.ts:1-19`), queued/running/parked lifecycle, follow-up steering, interrupt semantics, observer stream for webui.
- **LaneLedger** (`src/core/session/lane-ledger.ts:1-60`): machine-wide counting semaphore on the filesystem -- atomic exclusive-create slots, rename-onto reclaim with read-back so losers never clobber winners, mtime heartbeat leases provable by any host, `WeakRef` missed-release watchdog, documented residual race with argued bounds; filesystem errors fail OPEN by design (an unusable state dir must not deadlock every task). Top-level session turns occupy the same ledger (`turn-lanes.ts:1-30`), including holding through mid-turn question waits "so another model can't thrash the cache the user is about to return to." The phantom bare-name lane is capped by the tightest override so unplaced traffic can't bypass caps (`model-resolver.ts:56-80`, `lane-unplaced-capacity.test.ts`).
- Subagents via tools (`subagents/`, 451) with manager-profile gating (`agent.ts:877-880`); loop extension (`/loop` auto-refire with maxLoops) and loop-detect escalation ladder (nudge -> stronger nudge -> stop at t/2t/3t over canonical-arg-hash repeats and ping-pong, `loop-detect/detector.ts:1-16`).
- No token budgets on tasks; no crash-surviving subagents (workflows journal, plain subagents don't).

## Interop

MCP **client** only (stdio + HTTP/SSE, `mcp-client/transports.ts`, conformance-tested); no MCP server. No ACP. Headless: `-p` one-shot, `--json`, `--json-schema` structured output via a synthetic terminal tool validated against the user's schema (`ui-one-shot/structured-output.ts:1-6`). Own websocket protocol (AUTH handshake, uploads, question-input, task feed) + JSX webui with reconnect streaming replay (`agent.ts:279-287` currentStreamingContent). Published on npm (`publishConfig.provenance`) as the product itself; no SDK, no IDE surface, no import of rival histories/skills. Below pi's 6 (pi's RPC-mode docs are a deeper headless contract; hotdog's breadth beats pi's by having MCP at all, but its own protocol is undocumented as a contract). **5**.

5. Workflow machine-gates + judge nodes with filesystem-verified reconcile-resume (richer than cline's durable cron; less daemon-recovered than codex).
6. finish_reason=length call-refusal + universal orphan-answer discipline.
7. tool-call-repair grammar for leaked Hermes/antml/chatML call markup converted to real calls mid-loop, plus the bricked-history repair (corrupt stored tool-call args that 400 every subsequent request; `tool-call-repair/index.ts:1-14, grammar.ts:37-66`).
8. Zero-dependency source-tree distribution with a written supply-chain posture (`docs/supply-chain.md`) -- strongest such posture in the corpus (verified: `dependencies:{}`, bun.lock pins only @types/bun).
